**Recommendation: use a stable supervisor in the signer daemon, with replaceable v2 engines and a separate, persistent legacy owner.** FileStore owns durable poison; Engine owns the immediate stop; the supervisor owns recovery.

Reviewed integration `32fe19e` and B1s `d40024e`, including the complete builder notes. References below use **S** for [the spec](docs/plans/v0.2/approval-lifecycle-spec.md) and **P** for [the wave plan](docs/plans/v0.2/wave3-lanes.md).

**1. Required behavior.** An uncertain commit must poison storage and latch the owner’s stop before returning to its caller. Every subsequent v2 command/read returns `storage_uncertain`, including paths answered from projections. Cancellation follows the latch; a separate goroutine joins effects, retains the directory ownership descriptor, retries reopening at 1, 2, 4…30 seconds, and runs Startup under a fresh epoch. No old v2 memory survives; every old grant dies; legacy requests remain untouched ([S:1274](docs/plans/v0.2/approval-lifecycle-spec.md:1274), S:1998–2005).

Interrupted effects commit nothing and make no subsequent calls. Recovery preserves uncertain sends, supersedes unfinished edits, fills abandoned assist through Clock without another provider call, and reflushes outboxes with duplicate-identifiable event keys (S:1280–1288). Confirmed commits remain the prerequisite for effects and signature release (SA-7, S:1262–1265). Startup rebuilds indexes, reservations and unflushed work; existing quarantine, erasure and retention rules remain authoritative (SA-3, E18, E54, E73; S:1143–1172, 420–427, 726–730, 857–863).

**2. Actual implementation.**

- [`engine.go:132`](pkg/signerkit/lifecycle/engine.go:132) returns Commit/Remove errors without stopping or cancelling. `load` likewise propagates errors at line 96. Empty-result List bypasses storage at line 287; Vote resolves handles first ([`mutations.go:22`](pkg/signerkit/lifecycle/mutations.go:22)); Revoke can succeed without a store access at line 76.
- [`close.go:39`](pkg/signerkit/lifecycle/close.go:39) knows only `stopping → lifecycle_unavailable`; WaitMany has the same limitation at [`wait.go:92`](pkg/signerkit/lifecycle/wait.go:92).
- [`Run`](pkg/signerkit/lifecycle/reconcile.go:12) eventually stops and joins when a driver reports an error; ordinary command failures do not directly wake it. It explicitly requires replacement. [`startup.go:10`](pkg/signerkit/lifecycle/startup.go:10) already performs reconstruction, but nothing supervises replacement.
- Run preserves legacy resources, whereas [`Close:17`](pkg/signerkit/lifecycle/close.go:17) terminates them. Both shutdown paths close the generation’s v2 assist pool. Thus `Close → New(old.config)` destroys legacy requests and reuses a closed pool.
- [FileStore](pkg/signerkit/lifecycle/filestore_linux.go:224) poisons its cache correctly and provides manual held-inode Reopen at line 85. Its constructor releases ownership on initial reload failure at lines 75–77. Existing restart tests manually call Close/Reopen/New.

**3. Gaps.** Missing are the synchronous owner stop, uncertainty precedence on every path, automatic recovery ownership, safe dependency reconstruction, stable callback routing, initial-failure descriptor retention, and integrated fault tests. Store-only poison cannot close these gaps.

**4. Minimum design and lane ownership.**

| Lane | Required change |
|---|---|
| **A6 follow-up** | Add a latched stop cause and one `availabilityLocked()` guard; observe storage uncertainty under `Engine.mu` before releasing any failing operation. Cancel immediately; never join inside a committing actor. Make `Run(ctx) error` return the latched cause **after joining**. Add `Availability() error`. Extract `NewLegacyService(LegacyConfig)` with its own mutex, methods, contexts, reservations, tombstones, audit worker and assist pool; Engine.Close then closes only v2 work. |
| **B1s** | Keep Store’s four operations; explicitly contract typed `CodeStorageUncertain`. Add `AcquireFileStore(path, uid)` to acquire ownership without requiring successful loading. Keep `Reopen() error` and `Close() error`; retain the descriptor across failed loads. No independent engine restart inside FileStore. |
| **A7** | Implement stable `ApprovalRuntime`, attached once through `AttachApprovals`. Its configuration takes `RecoverableStore { Store; Reopen() error; Close() error }`, the legacy service, and `NewEngine func(Store) (*Engine, error)`. Its Run supervises generations; Close cancels recovery, joins everything, then releases storage. Expose recovery code/cause through Status. |
| **B1w** | Construct the durable runtime and engine factory; each factory invocation supplies a **fresh v2 assist pool**, including cleanup on failed construction. Wire configuration, startup diagnostics and process tests. |
| **A8** | Route callbacks through the stable runtime. Resolve against the persistent legacy owner and current v2 generation; preserve collision refusal and unknown-card auditing. Never capture an engine pointer permanently. |

The supervisor waits for the failed engine’s joined Run, backs off, calls Reopen, constructs a fresh engine through existing Startup, and publishes it atomically. Old engine references remain permanently stopped. Recovery stays `storage_uncertain` through reconstruction, even after FileStore clears its internal poison. Shutdown forbids later publication. Legacy preparation, delivery, deadlines and callbacks continue throughout.

**Rulings needed.** The behavioral requirement is determined; component ownership is not. P:285–291 assigns B1s the entire reopen loop while restricting it to file-store files; §5’s adopted split does not resolve that contradiction. Amend the allocation above explicitly. Define the atomic owner boundary as the enclosing `Engine.mu` critical section: store poison and engine latch both occur before `commitLocked` returns, without a callback that reverses lock order. Also clarify initial startup: ownership failures are fatal before Listen; recoverable listing failures complete initialization in a diagnosed `lifecycle_unavailable` state, retain ownership and retry. After an uncertain commit, uncertainty retains precedence until successful replacement.

**5. Acceptance proof.** Exercise every command’s landed/not-landed fault, including actor-owned commits, with eight concurrent readers/callers and empty-index cases. Assert immediate uncertainty, no post-stop commits/calls, no self-join, and completion under timeout/race/goleak. Run SA-11 crash-prefix/stop properties through the **automatic supervisor**; verify fresh epochs, dead grants, signature identity, uncertain-send suppression, edit supersession and outbox recovery. Hold legacy preparation/delivery/taps across repeated recoveries; verify duplicate reservations, tombstones and audit survive while new v2 submissions receive fresh assist capacity. Test backoff, initial FIFO removal, retained inode/flock, shutdown during reconstruction and stale engine references. B1’s stress and startup measurements remain separate outstanding acceptance work.
